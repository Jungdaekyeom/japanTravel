# 일본 여행 모바일 지도 웹앱 설계

## 제품 범위

- 여행 기간은 2026년 10월 2일부터 10월 6일까지 4박 5일이다.
- 정대겸(1993, 부산 출발)은 관리자이고 이규열·박준수·한규준(1998, 인천 출발)은 참가자다.
- 입국 공항은 간사이국제공항(KIX), 출국 공항은 나리타국제공항(NRT)이다.
- 앱은 Vercel에 배포하는 Next.js App Router 모바일 웹이다.
- Google Maps 위에 일차별 고정 경로를 한 번 애니메이션으로 재생한다.
- 공유 링크만 가진 사용자는 관찰자이고, 개인 코드를 입력하면 지정된 참가자 또는 관리자가 된다.
- 참가자는 자유문장 의견을 제출하고 관리자는 수동으로 승인 또는 반려한다.
- OpenAI, MCP, 카카오 API, GPS, 실시간 교통, 운항 정보, 오프라인 지도, PWA는 v1 범위가 아니다.

## 일정

1. 10월 2일: 부산·인천에서 KIX 도착, 하루카로 교토 이동, 교토 관광 및 1박
2. 10월 3일: 교토에서 오다와라로 신칸센 이동, 하코네 권역 방문 및 1박
3. 10월 4일: 오다와라에서 도쿄로 신칸센 이동, 도쿄 1박
4. 10월 5일: 도쿄 관광, 도쿄 1박
5. 10월 6일: 도쿄에서 NRT로 철도 이동 후 귀국

## 화면과 상호작용

- 767px 이하에서 앱을 표시하고 768px 이상에서는 휴대폰 접속 안내만 표시한다.
- `/terms`와 `/privacy`는 화면 폭과 무관하게 접근할 수 있다.
- 첫 화면은 전체 경로와 왼쪽 Codex형 패널을 펼친 상태로 보여준다.
- 패널에서 1~5일차를 선택하면 250ms 동안 접고, 지도 범위를 맞춘 뒤 선택 경로를 한 번 재생한다.
- 재생 후 전체 경로와 선택 일차의 강조선을 유지하고 재생 버튼을 노출한다.
- 날짜를 바꾸면 진행 중 애니메이션을 취소하고 새 날짜를 처음부터 재생한다.
- `prefers-reduced-motion`이면 완성된 선을 즉시 표시한다.
- 지도 로드가 실패하면 정적 일정과 재시도 버튼을 표시한다.

### 일차별 지도 연출

- 1일차: 부산→KIX 항공선과 인천→KIX 항공선을 2.4초 동안 동시에 그린 뒤 KIX→교토 철도선을 그린다.
- 2일차: 교토→오다와라 철도선을 그린 뒤 오다와라·하코네 핀을 강조한다.
- 3일차: 오다와라→도쿄 철도선을 그린다.
- 4일차: 이동선 없이 도쿄 영역과 관광 핀을 순차 강조한다.
- 5일차: 도쿄→나리타 철도선을 그린다.
- 항공선과 오다와라→하코네 보조선은 앱이 만든 곡선 또는 점선이며 Routes API를 호출하지 않는다.

## 역할과 공개 범위

- `observer`: 고정 일정과 사람별 최신 반려 한 건만 조회한다.
- `contributor`: 자신의 의견을 제출하고 자신의 반려를 수용한다. 이규열·박준수·한규준에게만 부여한다.
- `admin`: 모든 의견을 검토하고 승인·반려하며 철도 경로를 확정한다. 정대겸에게만 부여한다.
- 출생연도, 개인 코드, 세션 토큰, 의견 원문은 공개 응답에 포함하지 않는다.
- 승인은 작성자와 관리자에게만 보이고 공개 고정 일정은 자동으로 바뀌지 않는다.
- 공개 반려는 작성자별 최신 한 건이며 이름·제안 요약·반려 사유·수용 여부를 보여준다.
- 반려를 수용하지 않은 참가자는 새 의견을 제출할 수 없다.

## 데이터와 API

고정 여행 정의는 `src/trip/definition.ts`에서 관리한다. Supabase에는 `participants`, `sessions`, `login_attempts`, `opinions`, `route_geometry_cache` 테이블만 둔다. 브라우저는 Supabase를 직접 호출하지 않고 서버 Route Handler만 사용한다.

공개 API는 다음과 같다.

- `GET /api/trip/[inviteToken]`
- `POST /api/session/unlock` with `{ code }`
- `DELETE /api/session`
- `POST /api/opinions` with `{ targetDay: 1..5 | null, body }`
- `POST /api/opinions/[id]/accept-rejection`
- `POST /api/admin/opinions/[id]/approve`
- `POST /api/admin/opinions/[id]/reject` with `{ category, publicSummary, reason }`
- `POST /api/admin/routes/[segmentKey]/finalize` with `{ departureTime, naritaRailChoice? }`

모든 입력은 Zod로 검증한다. 의견은 1~1,000자, 공개 요약은 1~80자, 반려 사유는 1~300자다. 중복 승인·반려는 409를 반환하고 중복 수용은 기존 결과를 반환한다.

## 인증과 보안

- 초대 경로는 `/t/[inviteToken]`이고 서버 환경변수의 토큰과 constant-time 비교한다.
- 네 사람에게 서로 다른 6자리 숫자 코드를 발급한다.
- 코드는 `crypto.scrypt`와 개별 salt, 서버 pepper로 해시한다.
- 실패는 IP당 15분에 5회, 전체 15분에 50회로 제한한다.
- 성공 시 256비트 세션 토큰을 발급하고 DB에는 SHA-256 해시만 저장한다.
- 쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax`이고 2026년 10월 13일까지 유지한다.
- Supabase의 브라우저 직접 권한을 제거하고 모든 테이블에 RLS를 활성화한다.
- 검색 색인을 차단하고 `Referrer-Policy: strict-origin`을 사용한다.
- 로그에 코드, 쿠키, 의견 원문, 초대 토큰을 남기지 않는다.

## 철도 경로

Routes API 대상은 `kix-kyoto`, `kyoto-odawara`, `odawara-tokyo`, `tokyo-narita` 네 구간뿐이다. 2026년 9월 6일까지는 회색 점선과 `경로 확정 전` 배지를 표시한다. 9월 7일부터 관리자가 예정 출발 시각을 입력해 확정한다. 나리타 구간은 `skyliner` 또는 `nex`를 선택한다.

서버는 Google Routes API에 `TRANSIT`와 `TRAIN` 조건을 전달한다. 열차 단계가 포함된 첫 결과의 철도 polyline만 저장하며 공개 명칭은 `철도 이동`이다. 실패하거나 열차 단계가 없으면 기존 점선을 유지한다. 캐시는 생성 후 30일과 2026년 10월 7일 00:00 JST 중 이른 시각에 만료되고, 만료된 좌표는 응답에서 제외하며 매일 삭제한다.

## 갱신·오류·접근성

- 화면이 열려 있는 동안 30초 간격과 포커스 복귀 시 다시 조회한다.
- 지도와 외부 API 실패는 사용자에게 복구 가능한 상태와 재시도 동작을 제공한다.
- 패널 포커스를 관리하고 모든 버튼에 접근 가능한 이름을 준다.
- 상태는 색상만으로 구분하지 않는다.
