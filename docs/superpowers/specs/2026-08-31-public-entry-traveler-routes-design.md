# 공개 진입과 사람별 경로 재생 설계

## 목표

일본 여행 앱을 토큰 없는 공개 주소에서 모든 사용자가 같은 화면으로 이용하게 하고, 좌측 일정 패널에서 전원 또는 한 사람을 선택해 1~5일차 이동 경로를 재생한다. 이번 작업은 경로 경험을 우선하며 의견 검토 기능과 기존 인증·역할 백엔드는 삭제하지 않고 보류한다.

## 브랜치와 배포 기준

- `production`은 현재 공개 Production 복구 기준인 `d6e6290`을 가리킨다.
- `develop`은 최신 구현 `b7cf214`에서 시작하며 이 설계의 작업 브랜치다.
- 기존 `codex/japan-trip-app` 브랜치는 안전을 위해 유지한다.
- 이 설계 작업에서는 원격 push와 Vercel 배포를 수행하지 않는다.

## 범위

### 포함

- 토큰 없는 `/` 앱 진입
- 토큰 없는 `GET /api/trip` 조회
- 기존 `/t/[inviteToken]` 주소에서 `/`로 이동해 주소의 토큰 제거
- 역할과 세션 상태가 없는 공통 여행 payload
- 전원 및 네 사람의 수동 경로 선택
- 사람별 1일차 출국 경로와 5일차 귀국 경로
- 2~4일차 공통 경로
- 전원 또는 선택한 사람의 1→5일차 연속 재생
- 지도 핀의 사람 이름 제거
- 의견·관리 UI 진입점 보류
- README와 운영 인계 문서의 활성 앱 설명 갱신

### 제외

- 항공편명, 출발·도착 시각, 터미널 정보
- 실시간 교통·운항 정보
- 접속자 자동 식별 또는 선택 상태 영속화
- 의견 기능 재설계
- 기존 세션·역할·의견 API와 Production DB 삭제
- Production 배포

## 공개 진입과 공통 payload

새 루트 페이지 `/`가 모바일 여행 앱을 직접 렌더링한다. `TripApp`은 더 이상 `inviteToken`을 받지 않으며 `GET /api/trip`을 호출한다. 이 API는 일정, 확정 철도 geometry, 지도 선택에 필요한 여행자 ID와 이름만 반환한다.

활성 payload에는 `role`, `displayName`, `ownOpinions`, `reviewQueue`, `publicRejections`를 포함하지 않는다. 여행자 공개 정보는 버튼 표시를 위한 ID와 이름으로 제한하고 생년, 역할, 개인 토큰과 세션 정보는 포함하지 않는다.

기존 `/t/[inviteToken]` 페이지는 토큰을 검증하거나 클라이언트에 전달하지 않고 `/`로 이동한다. 기존 북마크는 계속 앱으로 연결되지만 이동 후 주소에는 토큰이 남지 않는다. 기존 `/api/trip/[inviteToken]`, 세션, 의견, 관리자 API와 DB 구조는 이번 작업에서 삭제하지 않으며 새 앱에서 호출하지 않는다.

## 의견·관리 기능 보류

`TripPanel`은 역할 배지, 관찰자 전환, 의견 작성, 반려 확인, 관리자 승인·반려, 관리자 철도 확정 UI를 렌더링하지 않는다. 해당 진입점에는 경로 개발을 위해 기능을 보류했으며 사용자 요청 시 공개 의견 모델로 재설계한다는 인라인 주석을 남긴다.

기존 컴포넌트, 보호된 API, repository 메서드와 Supabase 스키마는 그대로 둔다. 따라서 데이터 마이그레이션이나 기존 Production 의견 삭제가 발생하지 않는다. Supabase service-role 키는 계속 서버 전용이고 RLS 및 브라우저 직접 접근 차단도 유지한다.

## 여행자 선택 모델

공개 여행자 ID는 다음 네 값으로 고정한다.

- `daekyeom`: 정대겸
- `gyuyeol`: 이규열
- `junsu`: 박준수
- `gyujun`: 한규준

클라이언트는 `selectedTravelerId: TravelerId | null` 상태를 가진다. `null`은 전원을 뜻하며 첫 진입의 기본값이다. 좌측 패널 상단에는 `전원`, `정대겸`, `이규열`, `박준수`, `한규준` 순서의 버튼을 둔다. 사람 버튼 선택은 재생을 시작하지 않는다. 이후 `전체 일정` 또는 1~5일차 버튼을 눌러야 선택이 경로 재생에 적용된다.

사람 선택이 바뀌면 진행 중인 재생을 취소하고 다음 일정 선택을 기다린다. 선택 상태는 현재 페이지 메모리에만 유지하며 신원, 권한 또는 의견 작성자 정보로 사용하지 않는다. `전원` 버튼을 누르면 언제든 전체 경로 선택으로 돌아간다.

## 사람별 이동 구간

### 1일차

- 정대겸: 만덕터널 인근 → 김해국제공항 → 간사이국제공항
- 이규열: 이천시청 → 인천국제공항 → 간사이국제공항
- 박준수: 이천시청 → 인천국제공항 → 간사이국제공항
- 한규준: 수원시청 → 인천국제공항 → 간사이국제공항
- 공통: 간사이국제공항 → 교토역과 교토 명소

### 2~4일차

일본 내 모든 이동과 관광 지점은 네 사람에게 공통이다. 특정 사람을 선택해도 전원 선택과 같은 공통 경로를 재생한다.

### 5일차

- 공통: 우에노 → 나리타국제공항
- 정대겸: 나리타국제공항 → 김해국제공항 → 만덕터널 인근
- 이규열: 나리타국제공항 → 인천국제공항 → 이천시청
- 박준수: 나리타국제공항 → 인천국제공항 → 이천시청
- 한규준: 나리타국제공항 → 인천국제공항 → 수원시청

전원 선택에서는 중복 geometry를 복제하지 않는다. 이규열과 박준수의 이천시청 경로, 인천 출·도착 항공선처럼 같은 선을 공유하는 사람은 하나의 선에 여러 여행자 ID를 연결한다.

## 경로 데이터와 필터링

기존 지도 geometry를 유지하고 각 개인 구간에 적용 대상 여행자 ID를 구조적으로 연결한다. 공통 구간은 모든 여행자에게 포함되는 것으로 표시한다. 장소 좌표는 다음 기준을 사용한다.

- 정대겸은 현재의 만덕터널 인근 근사 좌표를 유지한다.
- 이규열·박준수는 이천시청 위치로 변경한다.
- 한규준은 수원시청 위치로 변경한다.

지도 라벨에는 사람 이름을 포함하지 않고 `만덕터널 인근`, `이천시청`, `수원시청`, 공항과 일본 장소명만 표시한다.

`buildDayLayers`는 날짜와 선택 여행자를 받아 공통 선과 해당 사람의 개인 선을 조합한다. 전원 선택에서는 그 날짜의 모든 개인 선과 공통 선을 반환한다. 필터링 후 재생 stage의 `lineKeys`, 초점 핀과 표시 핀도 같은 대상만 참조하게 해 선택하지 않은 사람의 출발지나 귀착지가 나타나지 않게 한다.

## 재생 상태와 순서

재생 요청 식별자에는 날짜뿐 아니라 `all` 또는 여행자 ID를 포함한다. 같은 날짜에서 사람을 바꾸거나 새로운 요청을 시작하면 기존 애니메이션과 카메라 이동을 취소한다.

- 전원 + 1일차: 모든 국내 출발 구간과 부산·인천 항공선을 함께 재생한 뒤 KIX 이후 공통 구간을 재생한다.
- 개인 + 1일차: 선택한 사람의 국내 출발 구간과 항공선만 재생한 뒤 KIX 이후 공통 구간을 재생한다.
- 전원 + 5일차: 공통 우에노→NRT 이후 부산·인천 항공선과 세 귀착 경로를 함께 재생한다.
- 개인 + 5일차: 공통 우에노→NRT 이후 선택한 사람의 항공선과 귀착 경로만 재생한다.
- 전체 일정: 현재 전원/개인 선택을 유지한 채 1일부터 5일까지 순차 재생한다.
- 감소 모션: 같은 경로 필터와 완료 순서를 사용하되 각 stage를 즉시 완료한다.

항공편명과 실제 시각은 데이터가 확정된 뒤 별도 작업으로 추가한다. 이번 작업은 현재의 고정 재생 시간을 사용한다.

## UI와 접근성

좌측 패널은 `제목 → 여행자 탭 → 전체 일정 → 1~5일차` 순서다. 여행자 탭은 좁은 모바일 패널에서 44px 이상의 터치 높이를 유지하는 가로 스크롤 목록으로 만든다.

여행자 선택 영역은 `tablist`, 각 선택지는 `tab`과 `aria-selected`를 사용한다. 날짜 버튼의 기존 키보드 포커스와 `aria-current` 동작을 유지한다. 라이브 상태 문구에는 선택한 사람 또는 전원과 현재 날짜를 포함하지만 지도 핀과 이동 라벨에는 사람 이름을 넣지 않는다.

사람 탭을 누른 직후에는 패널을 닫지 않는다. 일정 버튼을 눌렀을 때만 기존 250ms 패널 닫기 이후 재생을 시작한다. 패널을 다시 열면 현재 여행자와 날짜 선택 상태가 보인다.

## 오류 처리

공통 여행 API가 실패하면 기존과 같이 로딩 오류와 다시 불러오기 버튼을 표시한다. 기존 payload가 화면에 있는 상태에서 갱신이 실패하면 현재 일정을 유지하고 경고만 표시한다. 잘못된 이전 토큰 URL은 토큰 값과 관계없이 `/`로 이동한다.

사람별 경로 정의가 누락되더라도 공통 경로가 잘못 다른 사람의 경로로 대체되지 않게 타입과 테스트에서 모든 여행자·1일차·5일차 매핑을 완전하게 검증한다.

## 문서

README와 운영 인계 문서는 토큰 없는 공개 루트, 수동 여행자 선택, 보류된 의견·관리 UI와 `production`/`develop` 브랜치 기준을 설명하도록 갱신한다. 기존 인증·의견 백엔드는 삭제되지 않았고 활성 앱에서 사용하지 않는다는 점을 구분한다. 기존 개인정보·약관 페이지는 이번 경로 작업 범위에서 수정하지 않는다.

## 검증

- `/`가 앱을 렌더링하고 `/t/[임의값]`이 `/`로 이동하는지 검증한다.
- `GET /api/trip`이 토큰 없이 동작하고 역할·세션·의견 필드를 반환하지 않는지 검증한다.
- 기본 전원 선택과 네 사람 버튼의 접근성 상태를 검증한다.
- 네 사람 각각의 1일차·5일차 개인 선과 공통 선 조합을 검증한다.
- 이규열과 박준수가 동일한 이천시청 geometry를 공유하고 한규준은 수원시청, 정대겸은 만덕터널 인근을 사용하는지 검증한다.
- 2~4일차가 모든 사람에게 같은 공통 경로를 반환하는지 검증한다.
- 여행자 변경 시 진행 중 재생이 취소되고 다음 날짜 선택에서 새 필터가 적용되는지 검증한다.
- 전원과 개인의 전체 일정 1→5일차 재생, 다시 재생과 감소 모션을 검증한다.
- 지도 라벨에 사람 이름이 없고 여행자 버튼에만 이름이 표시되는지 검증한다.
- 세션·역할·의견·관리 UI가 활성 앱에서 렌더링되지 않고 관련 요청이 발생하지 않는지 검증한다.
- README와 운영 인계 문서가 공개 진입과 보류 범위를 정확히 설명하는지 검토한다.
- 전체 unit/component 테스트, typecheck, lint, Production build와 모바일 E2E를 실행한다.

## 완료 조건

- 토큰 없는 루트 주소에서 모든 사용자가 같은 앱을 본다.
- 전원 또는 한 사람을 선택해 요구된 1~5일차 경로를 재생할 수 있다.
- 1일차는 개인 출발 뒤 KIX부터 합류하고, 5일차는 NRT까지 함께 이동한 뒤 개인 귀국 경로로 갈라진다.
- 지도 이동 표시에 사람 이름이 없다.
- 의견·역할 UI는 보류되어 경로 경험만 남는다.
- 기존 인증·의견 DB와 API는 삭제되거나 마이그레이션되지 않는다.
