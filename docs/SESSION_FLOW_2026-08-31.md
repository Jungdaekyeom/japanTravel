## 1. 배포 404 확인에서 공개 진입점 재정의로 전환

세션은 전날까지 동작하던 배포본에서 404가 발생했다는 확인 요청으로 시작했다. 이후 공개 웹의 진입 방식을 다시 정리하기로 했다. 기존 개인 URL 토큰을 제거하고 누구나 동일한 루트 `/`로 접속하게 하며, 공개 화면에서 관리자·관찰자 같은 역할 구분을 없애는 방향이 확정됐다.

소스에는 토큰 없는 루트 페이지가 추가됐지만, 이 세션에서는 Vercel 배포를 수행하지 않았으므로 실제 배포본의 404 상태는 변경되지 않았다.

## 2. 여행자 선택과 지도 애니메이션 요구 확정

좌측 패널 상단에 정대겸·이규열·박준수·한규준 선택 버튼을 두고 다음 동작을 적용하기로 했다.

1. 여행자를 선택한 뒤 날짜를 누르면 해당 여행자의 일정만 재생한다.
2. 여행자를 선택하지 않고 날짜를 누르면 전원의 애니메이션을 재생한다.
3. 1일차와 5일차는 각 여행자의 국내 교통·항공 구간을 구분해 보여준다.
4. KIX 입국부터 NRT 출국 전 공통 일본 구간은 모두 같은 움직임으로 보여준다.
5. 이동 중 지도 위에는 사람 이름을 표시하지 않는다.
6. 여행자 선택 자체는 재생을 시작하지 않고, 날짜 또는 전체 일정 선택이 재생을 시작한다.

## 3. 공개 웹의 의견·관리 기능 보류

경로 개발에 집중하기 위해 공개 웹의 의견 수용·반려 UI와 경로 확정 UI를 제거하기로 했다. 관리 진입점은 공개 화면에 노출하지 않고, 기존 의견·경로 서비스와 API 및 Supabase 데이터는 호환성을 위해 보존하는 것으로 정리했다.

`AdminReviewControls`, `RouteFinalizer`와 해당 웹 컴포넌트 테스트는 제거됐다. `/privacy`와 `/terms`는 이번 변경과 무관한 기존 페이지로 유지한다.

## 12. 마켓 없는 앱 업데이트 방향 논의

한 대의 Android 폰만 관리한다는 조건에서는 RN을 유지하는 것이 가장 단순하다고 정리했다.

1. 서명된 내부 APK를 한 번 설치한다.
2. React 컴포넌트·스타일·JS 로직·이미지는 EAS Update로 전달한다.
3. Expo SDK, 네이티브 라이브러리, 권한과 Android 설정이 바뀔 때만 새 APK를 만든다.
4. Supabase 데이터는 서버 API가 다시 읽으므로 앱 새로고침으로 반영한다.

Native Android는 UI 코드 변경에도 일반적으로 새 APK가 필요하고, Flutter의 OTA는 Shorebird 같은 별도 서비스와 제약이 있어 현재 프로젝트를 다시 작성할 이유가 없다고 판단했다. EAS Update는 아직 설정하지 않았으며, 최초 OTA 대응 APK 빌드는 사용자의 별도 승인 후에만 진행한다.
