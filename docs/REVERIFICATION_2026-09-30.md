# 공개 지도 재검증 · 2026-09-30

대상: `develop`, 공개 여행 웹. 사용자 지시: 타이머 없이 재검증하고 커밋·푸시·Vercel Production 배포. Owner 앱, 인증·관리 API 계약과 저장 데이터는 유지한다.

## 확인된 결함과 수정

- 배경 점선과 진행 점선의 강조가 같아 이동을 알아보기 어려웠다. 배경을 흐리게 하고 진행 선 끝에 이동점을 표시했다.
- 국내 이동이 직렬화되어 있었다. 출발 순서를 유지하는 병행 stage를 복원했고 카메라 전환 간 최소 간격을 두어 부산 화면이 다음 카메라에 덮이지 않게 했다.
- 짧은 구간이 너무 빨리 끝나 보이지 않았다. 화면 거리 240px/s를 기준으로 최소 1.2초, 국내 병행 이동은 최소 2.2초를 보장한다. 실제 시각과 재생 초는 별개다.
- 먼 거리를 고배율로 이동할 때 흐린 지도를 통과했다. 먼저 줌아웃한 뒤 이동·확대하고, Google 벡터 렌더링을 명시했다. stage 시작은 타일 준비를 기다리되 이벤트가 없으면 2.5초 후 재개한다.
- 긴 장소명 때문에 핀 기준점이 밀려 화면 밖으로 나갔다. 핀 중심을 고정하고 라벨만 위에 배치·줄바꿈했다.
- 화면 크기가 바뀌면 재생 위치가 흔들렸다. 현재 진행률을 유지하고 남은 재생 시간과 카메라 범위를 다시 계산한다.
- 개인별 5일차 MAX 뷰도 최초 전체 뷰와 같게 했다.
- Next 빌드의 TypeScript 오류 무시 설정을 제거했다. API route에 있던 테스트용 factory를 인접 handler로 이동해 허용된 route export만 남겼다. API 처리 로직은 변경하지 않았다.

새 애니메이션 라이브러리나 범용 프레임워크는 추가하지 않았다. Ponytail 원칙으로 기존 RAF·Google Maps 기능을 사용했다.

## 자동 검사

Node 22.16.0 / pnpm 10.15.0. 지도 회귀 검사 후 전체 Vitest 47개 파일·223개 테스트, 타입 검사, ESLint, TypeScript 검증을 켠 프로덕션 빌드 통과.

Playwright 6개도 통과했다. Google Maps 키 없는 대체 화면·공개 UI 회귀 검사이며 실제 지도나 휴대폰 검사가 아니다. 별도로 실제 Google Maps가 로드된 프로덕션 빌드를 Codex 내장 Chromium에서 검사했다. 로컬 공개 일정 데이터는 배포된 `/api/trip`을 읽기 전용으로 전달하며 지도 응답을 모의 처리하지 않는다.

## 실제 지도 화면 검사

macOS Codex 내장 Chromium, 390×844 / 844×390. 시간 간격을 둔 화면 관찰이며 전 프레임 녹화 검사는 아니다.

- 최초 패널 닫힘, 열기·닫기, 날짜 선택, 다시 재생 확인.
- 1일차 국내 병행 구간의 카메라가 이천 버스 → 부산 차량 → 수원 차량을 각각 보여주며 진행점이 움직임. 부산 확대에서 기존 래스터 흐림 대신 선명한 벡터 지도 확인. 교토 관광과 호텔을 거쳐 2일차로 자동 전환.
- 2일차 신칸센·셔틀, 3일차 셔틀·JR·우에노 도보, 4일차 지하철·도보, 5일차 스카이라이너·귀국 항공·국내 귀가를 재생. 전체 일정의 마지막 ‘전원 전체 일정 경로 재생 완료’ 상태 확인.
- 3일차 재시작 도중 가로 전환 후 계속 진행. 재생 도중 4일차 선택으로 기존 재생을 취소하고 세로 복귀 후 정상 진행.
- 4일차 로스터리 핀의 DOM 범위가 x=47.5~60.5px로 화면 안에 있으며 긴 라벨도 줄바꿈되어 보임.
- 검사 페이지의 새 콘솔 오류 없음. 로그에 남아 있던 이전 Vercel 로그인 오류는 현재 지도 검사와 구분했다.

## 이전 작업에서 확인된 회귀

`fb42da7`에서 국내 이동이 순차화되고 배경/진행 점선의 식별성이 사라졌으며, 짧은 이동의 최소 시간이 빠졌다. Next route export 문제를 빌드 오류 무시 설정으로 넘겼던 부분도 이번에 원인을 수정했다. 반면 긴 라벨의 핀 기준점 문제는 `238fd9a`에도 있어 새 회귀로 분류하지 않는다. 기존 자동 검사만으로 실제 지도 애니메이션까지 검증했다고 보고한 것은 부정확했다. 이는 해당 변경·검증의 문제이며 모델 버전 전체나 고의에 관한 결론은 아니다.

## 남은 한계

- Android Chrome, iPhone Safari, 폴드 실기기는 연결되지 않았다. 390×844 등 브라우저 폭 검사는 실기기 검사로 간주하지 않는다.
- Production에 `GOOGLE_ROUTES_API_KEY` 및 서버 Place ID 설정이 없다. 실제 Maps 배경이 로드되는 것과 실제 길찾기 좌표가 검증되는 것은 별개다. 확인되지 않은 도로·버스·철도는 계속 근사 점선으로 표시한다.
- 이천 팀의 인천 T1 버스와 09:15 김포 항공편 정보 충돌은 사용자의 ‘넘어가’ 지시에 따라 미확정 상태다. 임의로 공항이나 항공편을 확정하지 않았다.
- 브라우저·네트워크가 Google 벡터 지도를 지원하지 않으면 래스터로 대체될 수 있다. Google 지도 로딩 실패 시 기존 정적 일정 대체 화면을 유지한다.
- 국내 병행 stage 안의 카메라 전환은 화면 밖 이동을 유지하기 위해 타일 대기로 정지하지 않는다. 실제 검사 환경에서는 선명하게 표시됐지만 느린 네트워크에서는 일시적으로 지도 세부 정보가 늦게 나타날 수 있다.
